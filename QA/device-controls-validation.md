# Automatic desktop/touch controls — revision 59

Real local Chromium / Three.js gameplay was tested through trusted keyboard, mouse and CDP touch input. The browser harness exposes staging and fixed-step simulation only in intercepted QA responses.

- `node QA/device-controls-browser.cjs`: desktop 1100×1000, narrow desktop 390×844, phone 390×844 and tablet 1180×900. Correct initial device mode; viewport width does not choose input. Desktop stick/action buttons/observer altitude buttons hidden, readable key reminders visible, cockpit touch UI hidden. Actual WASD motion in all four directions and Space ballistic jump pass. Trusted click captures mouse, queues exactly one full 25-charge beam (five damage ticks), and mouse movement aims. Held primary continues through an aiming drag using the capture-unavailable fallback. Right-click performs a real rescue dash, respects cooldown, costs no charge and does not fire. Pause, blur and hero exit clear input. Touch move+fire and scene-only aim pass; keyboard/touch switching updates layout and releases held input. Screenshots reviewed at all four sizes; no horizontal overflow or browser errors.
- `node QA/runner-left-controls-browser.cjs`: phone, narrow phone, fullscreen landscape and desktop pass. Original mobile controls remain on the left, at least 44px, inside viewport and non-overlapping. Simultaneous move/FIRE/ability input, scene drag, all four movement directions, cancel/blur/exit remain functional. Desktop now expects hidden touch controls and visible reminders.
- `node QA/hero-powers-browser.cjs`: desktop and phone regression checks for overload cost/cooldown and all three weapon interruptions, CPU interrupt, shield-absorption powered 1,680-damage stationary Violet beam, reset and evacuation targeting. Touch fixtures use actual taps; keyboard-to-touch transitions explicitly tap the scene before a touch ability.
- `node QA/weak-points-browser.cjs`: desktop and phone regression checks for real keyboard/touch firing against moving cores, final-core preservation, all heavy-weapon interrupts, once-only bursts and repeated cycles. The touch fixtures use actual taps so they select the intended input mode.
- Node regression checks pass: runner motion, heading, dash, charge, energy and hero roster.

Touch input is browser-emulated; physical phone/tablet performance is not measured. Mouse capture may be unavailable in an embedded or policy-restricted browser; drag aiming remains functional. Only Volt Rush currently supports player hero control; existing CPU heroes and helicopter gameplay are preserved.
